# Preparation and capability selection — v6.0

Planning owns selection, complete support assessment and pure construction;
TD owns common interpretation. Native execution belongs to Bindings, and live
logical authority/publication belongs to Servient. These are semantic contracts,
not an invented universal compiler/program representation.

The modern TD selection/compiler integration currently uses Host registrations
and funded definition owners. Those are implementation choices, not required
representations of prepared meaning. Core's borrowed `ValueExecution` can lend
the exact finite value content from that output to a different execution owner;
the lender retains its original storage and funding. A caller can also supply
the same checked source-independent meaning without invoking Planning at runtime.
Neither construction path bypasses actual native/codec/security qualification
or current instance permission. The constrained Read demonstration does not port
TD-driven preparation or establish a second schema/operation interpretation.

`PREP-ISOLATION-001`: Preparation MUST be bounded, side-effect-free local work
over TD-resolved facts and captured actual registrations/configuration. It MUST
NOT acquire sockets, sessions, tasks, credentials, handler calls or execution
permission. Selected output MUST own all required execution facts independent
of the source. Deferred input MUST own a bounded normalized snapshot including
mapping-relevant extension metadata, never a runtime source-TD callback. Pure
incremental construction may acquire capacity before each step; failure retains
provisional output and funded bounded rollback. Copy/atomic lowering is an
optional adapter, not open compiler eligibility. There is no universal
all-native-bounds-before-any-pure-start barrier.

`PREP-SELECT-001`: Support is the intersection of the exact operation, Form
context, protocol/subprotocol, payload/response formats and parameters, required
schemas, security, native address/matching semantics, profile and policy.
Selection MUST be deterministic and explainable under bounded candidates/probes.
An explicit selector narrows admitted meaning and cannot weaken security or
invent a different operation. Pair the actual compiler/executor/configuration,
codec, validator and security implementations: format/type/hash/operation/scheme
indexes alone are insufficient. Refuse ambiguity rather than select by accidental
registration order. Preserve native collection semantics. Candidate fallback
shares its work budget and MUST NOT silently retry uncertain effects.

For finite responses, selected support includes every primary/additional
alternative of that Form/operation: its exact media parameters, default or
response-specific data role/schema, declared success, actual validator and
unambiguous executable native identification. A Consumer may select supported
interactions from a larger TD, but cannot select only the convenient response
branches of an interaction. Producer qualification covers every alternative of
every advertised retained Form/operation, both before native setup and against
the final TD before publication. Unsupported branches cannot disappear from the
published description. Native status/header/content discrimination belongs to
the actual Binding, not common Planning. Scheme/type/media indexes do not prove
that complete pairing.

Common response preparation preserves additional-response order, applies TD
media/success defaults and resolves named schemas inside the selected semantic
closure. It prepays bounded schema construction/rollback before retaining the
owned response set; current preparation bounds additional constraints together
to 64 nodes and 4096 name bytes, at most 32 additional entries. Checked content
reuse compares the complete response set without reconstructing replacement
schema owners. Request media remains a distinct mapping operand; an unused
request role does not require an encoder for that media. Present unconstrained
response data and absent output remain distinct. Exact executable scope is
[response evidence](../evidence/td-responses.md).

`PREP-DEFER-001`: Consumer admission MUST normalize/index common meaning once
and return per-operation support information. Default admission requires at least
one statically supported interaction; a caller MAY require a stricter set. TD
tooling need not admit any executable interaction. Coarse eligibility and fully
prepared support MUST be distinguishable. Eager or bounded cancellable first-use
native preparation is permitted; a deferred Consumer candidate can still prove
unsupported. No operation executes before its complete selected preparation,
validation/security and capacity checks. First-use latency/failure is observable.
Warm execution MUST NOT rescan TDs or repeat shared defaulting. The optional
preparation coordinator owns work/input/waiters separately from live calls and
installs immutable results into generation-checked slots; execution-only
compositions report preparation required for unprepared Consumer operations.

`PREP-REUSE-001`: Prepared immutable content, local instance authority and native
infrastructure MUST have independent identities and lifetimes. Prepare-once /
checked-bind-many is permitted when the Binding establishes invariant dependencies
and valid operands, including endpoint/configuration/schema/security/profile
facts. A name/hash/type match grants no compatibility or permission. Each instance
retains fresh authority and its actual reference/operand/record cost; shared
backing retains its physical owner/original account until final release.
Specialized per-instance preparation is also valid; no parameter language,
universal VM, cache, persistence or generator is mandatory. A separate plan-set
epoch is required only when independently retained/replaced, not for every Thing.

`PREP-COVER-001`: Before Producer Serving, every retained final Thing-root and
affordance Form and each effective operation MUST have complete support under
the actual Binding/services/configuration and registered behavior or an explicitly
supported aggregation path. Check native addressing/matching, subprotocol,
formats/response branches, required schema rules, security, and promised Action,
subscription/cancel/Event-response behavior. One preferred Form/default operation/
security alternative or a draft Covered marker cannot certify others. There is
no live late-handler exception and no advertise-now/Unsupported-later policy.
A deliberately reduced TD must pass the complete final process itself.

Support may be established by constructing the mappings, or by the actual
Binding's equivalent complete support check followed by deferred pure
materialization. The latter is optional: it MUST establish every condition that
could discover Unsupported for the exact final description/dependencies. If that
cannot be separated reliably from construction, construct before publication.
The exposure separately pins executor/configuration and actual codec/security/
behavior registrations plus the funded materialization owner/input/coordinator.
The immutable definition contains no live handler/authority/cleanup obligation.
Materialization may fail from ordinary capacity/cancellation, but deterministic
unsupported meaning already present at publication is a qualification defect.
It completes before dependent native effects, dispatch or validated delivery.
An execution-only Producer materializes required data before installation.

Closed native setup can determine actual endpoints before final qualification.
Final TD revision, bound endpoints, provider dependencies, native collisions and
readiness MUST be rechecked before the local publication commit. Supplied Form
meaning cannot silently change. This supersedes freeze-before-all-effects,
always-eager Producer lowering and equality-only endpoint ownership as general
contracts. Native collision/multiplicity checks belong to the Binding; Engine
selection still requires an unambiguous actual owner of each selected mapping.

URI preparation validates base/templates. Dynamic variables use shared bounded
prepared expansion, followed by Binding-native address checks. Destination policy
and credential audience cover actual expanded/proxy/redirect/continuation targets.
A description is not permission to contact arbitrary referenced addresses.

Optional caches retain bounded work, waiters, negative-result policy and stale
completion/reclaim ownership. No unconditional single-flight/cache layout or
one-off operation resource schema is mandated without an actual cache contract.

## Existing implementation disposition

Whole-Thing Producer preparation also selects Property observe/unobserve and
Event subscribe/unsubscribe Forms against actual family-qualified notification
source registration. A Property source supplies no finite Read/Write behavior.
The MQTT capability interprets its
own resolved vocabulary, captures common prepared data meaning and the exact startup
registration, and rejects unsupported control data, dataResponse, response
branches, security or other effective operations. It creates no native subscriber
or socket during preparation. Composed publication binds the original native
mapping and actual validation/security services and rechecks complete final
meaning after closed installation. The concrete supported subset is owned by
[the MQTT README](../../protocol-bindings/protocols/mqtt/README.md).

The previous 2,180-line plan-set/API projection is superseded; its exact revision
is available at the v5.1 basis in the authority map. Current Planning Property
Read APIs remain restricted: the borrowed aggregate has eager all-bounds-first
ordering and the Host adapter accepts Copy atomic output. Their tests keep those
narrow claims. They MUST NOT constrain the successor compiler or be multiplied
per interaction family as its implementation. The authority migration itself implemented no replacement compiler or first-use
coordinator. The open finite Consumer path now uses the portable
`ConsumerCompiler` contract and generic owned Host erasure; the old support
carrier and sealed aggregate are explicitly named `InlineConsumer*`. The Host
Producer now also has a whole-Thing selector: each advertised Form/effective
operation asks the actual linked capability registrations for independently
owned concrete definitions; missing, ambiguous or behavior-less operations
refuse before native setup. Final support is checked again against those
registrations/definitions before publication. Opaque owned definitions are not
a universal program/session ABI; native readiness and collisions remain separate
Binding obligations. Consumer first-use coordination and broader service,
schema and security implementations remain outstanding.

Final whole-Thing checking walks the complete common meaning and compares each
original definition at its exact scope/Form/operation and actual registration.
The selected provider checks its existing definition and current dependencies;
other registrations perform complete support probes to detect new ambiguity.
This check does not construct a second retained definition set. Support probes
and final comparisons use the same matching/refusal semantics as preparation,
not operation/type/identity tags. Their sequential callback temporaries require
an actual declared peak bound before managed Host invocation; callbacks retain
no new controlled backing after return. A missing or newly excessive bound
cannot borrow unreserved capacity. A provider may temporarily materialize data
inside that funded bound; no allocation-free compiler representation is imposed.

## Open finite Consumer implementation

`open_consumer::ConsumerRegistry` captures actual startup compiler/executor and
codec/validation/access service owners. `ConsumerCompiler` declares cooperative
inspection, start, per-step, lifetime, abort and artifact-destruction bounds;
`Copy` and atomic output are not eligibility rules. General typed/static pairing
uses the same actual configuration contract without compiler-name tests. The
restricted `InlineConsumerCompilerSupport` is neither consulted nor issued by
open admission. Its old general public names and conversion methods are removed.

Basic admission and the existing common whole-description Form walk are reused
without Producer publication qualification. One paid semantic arena per Form
lends resolved `FormOwner`/operation facts to the actual candidates. The general
compiler input has no logical Property Read record or mandatory TD id. The
Consumer reports each Form/effective operation, including unsupported alternatives;
at least one selected interaction is required. TD Form order is the default
preference; multiple actual supporting providers within one admitted Form refuse.
An explicit binding/Form selector only narrows candidates after common services
have accepted the meaning. Selection keys include affordance kind/name and
operation, so same-named
Properties and Actions do not collide. The current finite facets are Property
Read/Write and `InvokeAction` with explicit `synchronous: true`. Continuing and
unspecified synchronicity use the separate Action facet below. Thing-root
ReadAllProperties, ReadMultipleProperties, WriteAllProperties, WriteMultipleProperties and QueryAllActions use the finite facet; other
collection operations use their distinct notification facets or remain unsupported.
Action input/output use distinct prepared schemas; absent roles permit no
application data. Repeating the Form's default response media preserves that
absence. A response-specific schema establishes a present value; different
media alone cannot establish a schema-less opaque result, and current common
preparation declines that combination for an Action without output. One actual
captured data service must execute every selected request and
response representation and constraint. Different media are allowed when that
complete pairing is qualified; they do not require a new codec abstraction.

Read and Write select independently on the same Property, including one Form
with default or explicit multiple operations. A Write captures the complete
supported Property value schema as input and no response value role. Property
readOnly/writeOnly declarations constrain eligibility even when a Form explicitly
contradicts them. Unsupported value assertions, effective security or concrete
Binding response mappings remain reported Consumer alternatives; a selector
cannot weaken them. Complete Producer qualification still requires every retained
effective operation, actual behavior and mapping. It cannot keep a Read while
silently dropping an unsupported advertised Write.

Eager `prepare` lends each `ConsumerCompilation` to a caller driver. Native
`step` is resumable under small caller credits while that single common semantic
loan lives. The entire native lifetime allowance is prepaid from the transaction
budget shared by alternatives; per-step credit cannot renew it. Early driver
return, cancellation, failure or invalid output aborts under prepaid rollback.
Cursor/output slots, declared indirect backing, callback scratch, original parent
leases and aggregate retained destructor work are acquired/qualified before
start. There is no partial installation or native I/O during preparation.

`ConsumerExecutionContent` captures immutable affordance, operation, selected security requirement and data-role
meaning without endpoint, service, authority, policy or account fields.
`PreparedConsumerContent` is its funded Host owner. Ordinary preparation constructs
that content once; `prepare_with_content` qualifies actual endpoint mappings for
one retained operation by comparing borrowed source assertions against the same
content. The reusable subset includes Property Read/Write value constraints and
ReadAllProperties member constraints. Included member names,
order and complete supported assertions must agree for the collection; nested
object fields/required names compare by meaning, independently of source order.
No replacement constraint/member/name tree is built. Unsupported or changed meaning refuses. Other Forms remain
reported Consumer alternatives, rather than becoming Producer qualification.

Every selected mapping still passes common Form/security/media/URI checks, actual
provider selection, complete data-service support, native compilation and capacity
checks. `ConsumerDefinition` retains the shared content, exact native mapping,
actual executor/configuration and data service with captured bounds. A change to
native literals, headers or template instructions requires actual native
preparation; changing values within a qualified dynamic mapping is interaction
work and requires no replacement definition. Content reuse grants no native
artifact compatibility. Native compilation remains owned/incremental,
and no TD, parser, semantic arena or compiler survives the completed definition.

`type_schema::prepare_schema` captures the bounded structured subset defined in
[Core](interaction-core.md). A bounded borrowed census checks supported assertions,
nodes/names/depth and prepays recursive construction/rollback before allocation.
Scalar input/output roles now own their dynamic constraint storage; their actual
bytes and disposal work are no longer zero. Reuse uses `matches_schema` or the
named-member comparison against borrowed TD facts, without compiling another
constraint tree. Actual data services still qualify the retained complete schema.
Finite, continuing Action and Notification preparation share the same borrowed constraint
census, construction and compatibility interpretation. `prepare_type_schema`
remains an explicit narrower participant facet; it is not a consequence of a
continuing lifetime. Root Action status and actual MQTT collection mappings
retain narrower implementation subsets. A JSON service alone does
not extend a native participant's admitted operation/profile scope.

HTTP Producer selected-definition final checking compares borrowed normalized
constraints against the original program and retains its existing schema owner;
it no longer recompiles a second selected constraint tree merely to compare it.
Other providers still need complete actual support probes, with declared scratch.
Native endpoint lowering and whole-description admission remain separate work;
this does not establish general normalized-TD reuse or native retargeting.

`ConsumerDefinition::bind` attaches a retained actual access policy and independent
instance bank without recompilation or source callbacks. `ConsumerBinding` is the
association handoff; Servient attaches its independently current
`ConsumerInstanceRef` without allocating call slots. Work capacity and its account
are chosen separately at finite admission, as specified by
[Runtime Safety](runtime-safety.md) and [Foundation](foundation.md).
Bindings may share content or an unchanged qualified mapping while preserving
separate permission, records, call/result/cleanup accounts and native limits.
Changed captured service bounds cannot be refreshed by binding another instance.
Refusal returns the original mapping/policy owners. The convenience `prepare`
result supplies bindings at the preparation bank; callers can retain definitions,
discard those initial bindings, and bind independently after source retirement.

`ConsumerRegistry::try_new` adopts raw data/access services at its explicit bank,
matching raw aliases only within those inputs. It is a startup convenience for
services not independently adopted elsewhere. Cross-registry/Servient service
composition uses `ConsumerRegistry::try_from_retained` with
`RetainedConsumerRegistrationInput`: actual preparation plus separately retained
data and access owners. The composition root adopts each physical service once
with `ConsumerServiceOwner::retain_data` / `retain_access` and propagates that
owner. Adoption refusal returns the complete raw input. Import retains its
original bank without recharging/transferring backing, including when the data,
access, registry and instance banks differ. Changed backing declarations refuse
import rather than refresh the original owner. Complete actual qualification and
fresh per-instance access/security checks remain mandatory.

Both constructors separately reserve registry-only records/references and each
actual native registration. Partial refusal rolls back new local reservations
and returns all protected inputs without refunding pre-existing service owners.
Registry records retire when their registry does; prepared users keep the original
service/native owners through normal and late result disposal, in either root
retirement order. Mapping/content backing and instance records have separate funding.
See [Foundation](foundation.md) for physical retention and accounting. This is a
Host representation of the boundary, not an Arc field or executor requirement on
semantic content or a new all-profile execution claim. Host startup reference construction uses
the existing trusted Host allocation policy; fallible native compiler-slot and
owned-cursor allocations are exercised independently. This is not an allocator
interceptor or a claim of recoverable process-wide OOM.

## URI-variable preparation

PREP-SELECT/COVER/REUSE-001 apply to the complete effective variable meaning of
each selected interaction. Common preparation uses TD's effective-scope view,
qualifies every retained declaration/schema assertion, checks RFC expression
support and declaration coverage, and owns source-independent names, schemas
and reference requirements. Native compilation qualifies expression placement
and actual configuration compatibility. It does not reinterpret DataSchemas.
Reuse compares effective schemas and reference requirements without constructing
another shared content owner; different native literals/addresses may share this
meaning under separately qualified mappings.

An unresolved template is not a concrete destination or credential audience.
Definition/instance preparation checks actual services and native eligibility;
it defers actual-destination permission to paid pure native resolution and fresh
instance authorization for each interaction. This grants no permission to make
I/O during preparation/resolution. Static mappings retain their preparation
destination check. Unsupported selected assertions or missing native resolution
support refuse the candidate, with no fallback during accepted execution.

Producer qualification remains complete for the entire final description.
Dynamic publication requires fully supported native matching/captures, variable
validation, collision handling and all advertised operations before Serving.
A Consumer expansion utility cannot establish that claim. The current HTTP
finite Property Producer continues to refuse URI-variable declarations/templates, including
unused retained declarations. It never drops them to obtain qualification.
Existing qualified native Action continuation-ID mappings retain their separate
profile; they do not acquire general caller-supplied variable support here.

## Continuing Consumer Action preparation

`ConsumerActionRegistry::prepare_action` admits one Action through the common
Basic/semantic Form walk and captures source-free invoke/query/cancel mappings.
One paid semantic loan serves all effective operations of a Form.
It accepts absent or false synchronicity; explicit synchronous Actions retain the
finite facet. Each described control operation must have a supported selected
Form; absent controls stay unavailable. Form order is the default preference,
selectors only narrow applicability and ambiguity within a Form refuses.
Each operation can select a different actual registration, configuration and
access service. The control mapping explicitly proves compatibility with the
original invoke mapping before the association can execute. Registration equality
is neither required nor sufficient. No generic continuation URL is constructed.

The actual `ConsumerActionPreparation` compiles pure bounded native mappings,
while Planning prepares the same bounded structured data meaning as finite
execution and checks the current endpoint NoSec subset. Input and output are
independent `ValueSchemas` roles. A borrowed census prepays construction and
rollback work, checks aggregate destruction against the cleanup-step allowance,
and reserves variable backing before constructing the constraints. One original
owned pair serves invoke/query/cancel selection; subsequent semantic loans compare
borrowed assertions without rebuilding it. Each actual selected service still
qualifies the complete retained schemas. No native compiler needs to interpret
them again to obtain the same common meaning.
Native vocabulary, variable address placement/matching and response conventions
stay in the Binding; variable scope and DataSchema interpretation are shared.
The association owns every selected mapping, both Action data roles, actual
services and original funding after all TD/compiler owners disappear.
`ConsumerPreparationBounds` replaces the notification-specific bounds name for
these two pure typed preparation facets. Declared work must fit the caller's
configured compilation allowance; short/unfunded preparation invokes no native
effects and releases partial owners. The supported HTTP callback requires an
explicit 4096-unit preparation allowance, as does the existing MQTT facet.

## Open Consumer notification preparation

The typed `open_consumer::ConsumerNotificationRegistry` is the notification
facet beside finite preparation. Its operation-scoped `prepare_notification` reuses
common TD admission and the resolved Form loan with an explicit notification
kind and target, selecting one named observable
Property's observe Form, Thing-root observe-all/subscribe-all Form or Event's subscribe Form in TD order or by explicit
selector. Unsupported alternatives
are skipped; missing support and multiple complete actual providers refuse.
It does not claim whole-Thing Consumer support or Producer qualification.

`ConsumerNotificationPreparation` extends the actual source-free notification
Binding registration with a bounded pure compilation callback. Its schema operand
borrows the original complete role meaning; native compilation must not rebuild
that meaning or retain a source loan. External linked
Bindings can implement it without a finite capability, compiler-name test or
Core protocol case. The current eager typed facet prepays the complete declared
callback/temporary/retained bounds and rollback; it introduces no universal
compiler, asynchronous preparation coordinator or first-use cache. Metadata,
support and clone/drop callbacks remain trusted finite local work.

The selected `ConsumerNotificationDefinition` owns the actual Binding/program,
configuration, family-qualified target, endpoint/Form, concrete data and
access services and original Host funding. The shared role selector
`prepare_notification_schemas` uses the same structured normalizer for a readable
Property, each of the four Event roles and each named collection member. Its
borrowed census prepays variable construction, rollback and destruction; exact
retained field/name backing moves to the definition. Runtime capture retains
that original funded definition instead of cloning constraint trees. Selected
MQTT Producer final checks use `matches_notification_schemas` against borrowed
final TD facts; native compatibility and whole-TD coverage remain independent.
`NotificationSchemas::PropertyValue` captures the Property's
own DataSchema and requires `observable: true`; it cannot acquire Event control
or reciprocal-response schemas. The `ObserveAllProperties` variant owns the
named readable collection schema; it is not a scalar Object assertion. It shares
member backing between the definition and captured validator without copying
names per cursor. The `Event` variant retains separate
subscription/data/dataResponse/cancellation schemas. Neither its program nor runtime
retains a source TD/semantic loan/compiler. Each present role requires complete
supported schema/media meaning. Required native responses still need actual
support/cardinality; a schema alone cannot invent it. No native I/O occurs in
preparation. Current MQTT support and its explicit control/response refusals are
defined in [the MQTT subset](../../protocol-bindings/protocols/mqtt/README.md).

Property selection authorizes `ObserveProperty`; captured runtime policy uses
that operation for establishment/delivery and `UnobserveProperty` for mapped
stop. Preparation neither executes a Read nor captures an initial value. Native
Form semantics and stop support remain the concrete Binding's responsibility.

Root notification preparation selects the actual Thing Form and authorizes
`ObserveAllProperties`; runtime establishment/delivery and mapped stop use the
corresponding root operations. It derives every non-writeOnly member schema
from the shared TD loan, independently of leaf Forms and observability hints.
Its bounded member census, construction/disposal work and temporary schema
backing are paid before construction; selected definition funding retains the
schema until final disposal. Collection data services must explicitly support
the full named map; scalar Object support cannot qualify them. The current
MQTT mapping requires both operations on the same root Form. Other root control
topologies require an actually implemented Binding/preparation facet.


Event-root selection instead captures every Event's exact name and all four
independent schema roles in `EventCollectionSchema`. The shared semantic loan
contains Event declarations and local contexts, without their individual Forms.
An unrelated root operation acquires no Event schema closure. Construction and
disposal walks and variable name/table backing are funded before construction;
selected definitions and captured validation share the original backing. Scalar
schema support qualifies each Event role; no full Property-map decoder is used.
The actual Binding must prove native attribution and supported control/response
roles. The current joined control subset refuses member subscription/cancellation
data; no common aggregate wire encoding is inferred. MQTT additionally refuses
any member dataResponse and requires supported data for every Event, a combined
root Form and terminal single-level wildcard. Unsupported assertions in any
included Event refuse the whole candidate. Selection authorizes SubscribeAllEvents;
execution retains it for establishment/delivery and UnsubscribeAllEvents for mapped
stop. Complete Producer qualification rechecks every root/leaf Form, member role,
source, actual native definition and final retained TD. See the
[collection contract](interaction-core.md) for occurrence identity and response
validation and the [MQTT policy](../../protocol-bindings/protocols/mqtt/README.md#thing-root-event-subscription)
for the concrete native mapping.

## Thing-root Property collection preparation

ReadAllProperties/ReadMultipleProperties/WriteAllProperties/WriteMultipleProperties select actual root Form/operation/Binding
coordinates using the same per-Form semantic loan and actual startup registrations. A Property
Form is never a fallback collection Form. Consumer selection may retain a root
operation when individual Property Forms are unsupported; complete Producer
qualification still requires every retained Form/effective operation and its
actual behavior/native participant. Unsupported collection alternatives remain
reported by the Consumer, rather than authorizing an invented protocol mapping.

`prepare_readable_property_schema` derives owned names and supported member assertions
from TD's resolved Property schema loans, independently of individual native
read mappings. Distinct `ConsumerFiniteSchemas` variants capture all-read versus
selected-read meaning. The latter requires actual request encoding, the generic
Array input validator invoked on the encoded request, and exact selected-result
validation support; selection-specific encoding/result facets alone cannot
qualify it. All-read support acquires no generic Array input requirement.
Preparation captures the complete eligible schema and performs no invocation
encoding. Each invocation validates its own bounded set against that immutable
schema, funds the complete encoded input before acquisition, and retains an inline
selection independently of native ownership of the request. URI-variable
expansion and native encoding are not universal Engine query conventions; the
current native slice declines URI templates/variables. Preparation funds retained member/name backing and bounded destruction
as well as artifacts/services; temporary construction remains inside the existing
common admission allowance. Native preparation performs no reads or aggregation.
The borrowed member census prepays `CleanupItems` before schema vector/member
acquisition. Finite Consumer preparation moves that schema into its funded
content owner; native mappings and instance bindings retain references rather
than cloning the table. Reuse compares borrowed assertions and acquires no new
schema destruction obligation. Every actual constructed owner has its original
member-count-plus-vector disposal allowance; partial construction, cancellation
and late refusal use that paid credit. Rollback bounds include retained and
provisional owners conservatively. Producer paths that construct additional
owners still fund each actual construction. A short payment reports capacity
refusal rather than an unsupported alternative.
Final Producer qualification compares the original complete member meaning,
root coordinate and selected actual registration after closed native setup.
Changing an included schema, role eligibility or member set invalidates prior support.

`prepare_writable_property_schema` independently derives every non-readOnly
Property, including writeOnly members. `ConsumerFiniteSchemas::WriteAllProperties`
retains this complete **input** map; it has no output schema. Its captured actual
data service must support named-map validation; generic Object validation alone
cannot qualify it. The runtime invokes that complete map validator under the
captured work policy, then rechecks group authorization and all dependencies
before native admission. It does not invoke an additional generic Object
validator, selection encoder or individual Property operation. The same member
census, temporary construction allowance, retained funding and cleanup prepayment apply to the
writable role. Native preparation performs no writes.

`ConsumerFiniteSchemas::WriteMultipleProperties` retains that same complete
writable eligibility independently of a per-call subset. It requires the actual
`supports_property_write_selection`/`validate_property_write_map` facet; generic
Object validation, all-map validation and selected-read support cannot qualify it.
The captured pure validator derives the selection only after validating every
supplied value. Admission retains that inline set before transferring the input,
then invokes fresh set-aware permission and rechecks dependencies. It performs
no selection-array encoding. Final Producer comparison includes the original
eligible writable schema, even when one invocation selects fewer members.

The supported schema and HTTP subset are scoped by the
[collection contract](interaction-core.md) and
[HTTP mapping](../../protocol-bindings/protocols/http/README.md#thing-root-readallproperties).
This adds no universal compiler, eager collection plan set, first-use coordinator,
new gate or implementation claim for other collection operations.

## Thing-root Action status preparation

Action and Event collection preparation coexist in one TD. Each effective
operation selects its own family schema and services: QueryAllActions captures
Action output/status validation, while SubscribeAllEvents captures each Event's
separate roles and occurrence validation. A loan containing both families does
not substitute one table for the other. Whole-Thing Producer qualification still
requires both root behaviors, every advertised leaf mapping and the complete
final TD, including each family's duplicate-expanded-role checks. Distinct actual
native participants may implement these operations under one logical instance.

QueryAllActions selects an actual root Form and finite exchange; it MUST NOT
select N Action controls or require Consumer invocation handles. The root TD loan
lends Action definitions and their distinct schemas without individual Forms.
Planning captures each exact name and supported output role in
`ActionCollectionSchema`, under prepaid name/backing and rollback bounds. Input
schemas do not become query inputs. A concrete status validator must establish
complete representation support; a scalar Object validator cannot qualify it.
Duplicate expanded output assertions, unsupported required output constraints,
security or response semantics refuse preparation. QueryAllActions qualification
checks every resolved response predicate, including non-HTTP extension assertions;
only supported unique response instructions and the Binding's supported class
annotations are admitted. Another supported leaf cannot make that root selected.
Consumer partial support may still execute a supported root without executing
unrelated leaf mappings.

Complete Producer qualification additionally requires the actual root policy,
all described Action operations, their original validation/control services, a
captured root route and the concrete Binding's complete native inventory. The
same immutable member meanings and services are checked against the final retained
TD at managed admission and again after closed native setup before publication.
A prepared root definition or installed listener alone supplies none of the
missing obligations. No dependency, gate or milestone changes follow from this
bounded increment.

## Selected executable security preparation

`security::prepare_security` projects complete effective security from shared TD
facts, including Form replacement of Thing requirements, conjunctive lists and
nested Combo alternatives. Standard scheme operands, proxy and requested scopes
remain part of meaning. Absent optional credential names stay absent; only a
concrete Binding supplies protocol-specific placement defaults. Unsupported interpretation (such as extension assertions)
becomes an explicitly unavailable leaf, never NoSec. Cycles, malformed combinations
or bounded expansion failure refuse the whole expression before selection.
Structural dependencies and full standard expansion counts remain checked even
inside a proxy-bearing or extension-bearing unavailable Combo; opacity cannot
hide a cycle or reduce its processing cost to an anonymous branch.
Public typed inputs must pair each built-in discriminator with its matching TD
variant; `Extension` carrying a built-in name refuses before selection rather
than concealing its standard semantics as unavailable extension data.
The current projection admits at most 64 visited nodes, depth 8, 16 complete
alternatives and 4 non-NoSec components per conjunction; its 1024-unit text/operand
envelope also charges reference/scheme names and 32 units per parameter. These
are processing limits, not authentication protocol support. Temporary construction,
expansion and rollback are prepaid; selected variable backing/destruction belong
to the original prepared content owner.

Consumer preparation tries complete conjunctions in declaration order. For each
