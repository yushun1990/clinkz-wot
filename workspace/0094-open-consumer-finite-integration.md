# Open finite Consumer preparation/execution

Status: MIGRATED

The approved open Consumer plan identified a real admission seam: generic owned
incremental compiler erasure worked, while general-looking Consumer capture
required the inline adapter's closed support/layout assumptions. Source review
confirmed that this was not a reason to invent a new compiler, universal runtime,
first-use cache or notification lifecycle.

Selected: retain generic portable compiler/Host erasure, original typed runtime
registration, Core owned artifact storage and finite result/cancellation controls.
Add an explicit public compiler cost/configuration contract, deterministic
TD-resolved selection and source-independent actual service/execution pairing.
Move completed definitions and the shared opaque bank to Core; keep pure selection
in Planning and logical finite calls/cleanup in the source-free Servient slice.

Rejected: removing only the downcast or issuing a generic private support flag
would preserve unproved Copy/atomic destruction costs. Requiring all retained
Consumer Forms to be supported would copy Producer publication rules incorrectly.
Making Planning depend on Servient would reverse the module boundary. A second
compiler erasure or a generic RPC/session abstraction adds no working capability.
Retaining the old general names as aliases would conceal the restricted adapter.

The portable contract and Core carriers are migrated to Planning/Binding SPI and
module-boundary owners; WP-200/WP-400 own implementation scope. The standalone
Cargo-linked datagram participant and public HTTP path provide executable evidence.
Original result, cancellation, capacity and cleanup mechanisms remain in use;
no SSE implementation, new acceptance gate or milestone transition is introduced.
