# Consumer Property Read Architecture Gate

Machine-readable gate status, fixture roots, dependencies, evidence paths and
commands are owned only by
[`consumer-property-read-architecture-gate.toml`](consumer-property-read-architecture-gate.toml).
This record defines the bounded cross-package claim and its acceptance obligations.

ADR-0021's inline ordering amendment changes the original bounds-first compiler
contract. Existing acceptance and recorded measurements remain scoped to their
named revisions; neither covers the open inline implementation automatically.
The evidence inputs below include replacement qualification, sequential rollback
and installed-path cases for fresh independent exact-head review. Updating those
inputs does not change gate status or claim acceptance of the amendment.

## Purpose and prerequisite boundary

This is the Consumer one-shot proof required by the architecture backbone and
ADR-0019 under active v5.1 authority, refined by ADR-0021. It joins borrowed typed
TD admission, complete eager Planning output, Consumer-only Core registration,
Servient publication, selected outbound execution, response validation, generation
retention and terminal cleanup in Host and application-static representations.

The work-package index owns admission/completion/impact states. The gate manifest
links the exact ten-tranche prerequisite closure, including the completed
`WP-400-CONSUMER-PROPERTY-READ-RUNTIME` and its seven direct predecessors.
The remaining two are their transitive call-value and planning inputs. All linked
completion evidence must remain current and passed. Broader package completion is
not a prerequisite and is not implied.

The accepted Producer `PROPERTY-READ-ARCHITECTURE` gate remains independently
registered with its existing acceptance and evidence. Its inbound route/handler
proof does not establish the Consumer call/lease topology. The accepted Consumer
Runtime tranche supplies a candidate composition, but its package acceptance does
not accept this architecture gate. Initial registration authorizes review of
that existing candidate; it admits no new source tranche or architecture change.

## Production path and legal inputs

```text
caller-owned immutable typed Thing + complete client-only registration + checked policy
  -> Servient paired build/cleanup and real parent capacity
  -> TD whole-input inspection, shared Basic and paid semantic lending
  -> Planning all-readable preflight and complete materialization
  -> sequential pure bounds/start/progress with funded whole-output rollback
  -> pure eager compiler output and source-independent Frozen owner
  -> consume build owner, end source/config/compiler loans, finish scratch cleanup
  -> Servient final registration/identity/generation/capacity/cancellation checks
  -> private permit and preallocated atomic Published installation
  -> destroy caller Thing
  -> read_property(name, options), exact generation lease and compiled coordinate
  -> name-free OutboundRequest and installed Core registration
  -> owned decorated Host call or complete associated-state static slot
  -> Core-sealed normal or late result, acknowledgement and opportunity release
  -> drain, bounded Planning reclamation and child-before-parent terminal release
```

Tests may provide legal root inputs: typed Thing content, complete binding/compiler
registration, prebacked protocol results, clock, work/resource policy, URI variables,
selection controls and cancellation timing. They must not replace the production
path by fabricating a `ValidatedThing`, semantic event, logical plan, Frozen draft,
artifact reference, selected `OutboundRequest`, runtime publication permit,
generation lease, Core validation seal or cleanup authority. The binding may author
its own protocol/compiler state and result metadata through its raw public SPI;
the installed Core owner still validates that output. Raw-client invocation from
the application, legacy consume/client selection, TD/Form rescanning at execution,
or a second validator/selector/reclaimer cannot satisfy the aggregate proof.

Host owns the unique output/rollback bridge and reparks the complete original
Planning owner after exclusive checkout. Callbacks run outside structural locks;
the driver retains its root and generation while outside the lock. Static retains
the actual typed registration, Planning root and associated-state slot in caller
storage. Both retain the original cleanup account and real parent reservations
until physical owners settle. Their physical containers and progress APIs differ.

## Evidence allocation and limits

The two registered downstream fixture roots already exist:

- `consumer-property-read-binding` authors the finite client-only Host/static
  binding and real compiler registration. It inspects compiler-produced targets,
  uses prebacked variable results and recoverable Host call backing, and supports
  deterministic normal, rejection, validation, cancellation and cleanup outcomes.
- `consumer-property-read-runner` supplies normal-library public application entry
  points. Both consume a real typed Thing, destroy it, read two non-first original
  Form coordinates, receive sealed status 599 and explicitly shut down with zero
  parent charges. Its actual static library compiles for ARM without an executor.

The standalone application assertions cover successful public composition. They
do not independently assert the entire cancellation, corruption or resource
matrix. The registered `servient/tests/consumer_property_read` integration tests
use that same external binding and production public Runtime for those cases.
They assert exact compiled target bytes, payload bytes, shared normal/late error
categories, exactly-once settlement, publication boundaries, retained generation
and parent capacity, and terminal destruction. The private final-check unit test
supplements public interleavings with mutable-identity fault injection; it cannot
substitute for public publication evidence. The registered aggregate-admission
fixture observes actual compiler bounds/starts, sequential failure precedence,
funded later-bounds rollback and zero starts before materialization/qualification;
Runtime rejection tests separately observe no client invocation or publication.
Those counters measure different effects. TD/Core/Planning tests protect their
own semantic and ownership boundaries, rather than standing in for composition.

The existing Runtime completion evidence owns exact measurements, author bounds,
toolchains, executable revisions and its six package obligations. Reuse those
facts without relabelling its `passed` state as a gate pass. Gate commands must
run against the exact candidate revision; the review must check that referenced
implementation and concrete fixture author contracts remain applicable there.
The registration PR records its own executions and exact head in GitHub.

## Remaining acceptance obligations

A fresh independent architecture reviewer must reconstruct and explicitly accept
the following at the exact reviewed head, using the manifest's commands, source
audit and executable assertions. A green structural checker or required GitHub
diff-hygiene status does not establish any of these conclusions.

| Obligation | Required falsifiable evidence |
| --- | --- |
| Complete public composition and provenance | Both downstream applications use real TD admission, all-readable Planning output, complete client-only registration and public Servient publication/calls. After source destruction, explicit original Form selection resolves distinct real compiled targets. Audit the no-fabrication and no-legacy boundaries above; a status-only assertion is insufficient for coordinate correctness. |
| Whole transaction and publication | Validation/materialization/bounds/final-check/allocation failure and abandonment retain the original whole unpublished owner and cleanup account. Sequential pure lowering may leave earlier artifacts on later bounds failure; funded rollback destroys each once. Earlier progress failure wins over unevaluated later bounds. Pre-materialization/qualification failures start no compiler. No failure invokes a client or publishes a subset. Zero/short/exact final credit and real cancel-before/cancel-after ordering establish private permit linearization and an allocation-free, callback-free, non-yielding install. |
| Selected call and shared validation | Installed Core produces a name-free selected request, retains its one-use seal with the complete call/slot and preserves normal, immediate-late and polled-late identity/shape/error rules. Rejection recovers original input before effects; accepted overrun remains accepted cleanup. No automatic fallback or runtime TD query occurs. |
| Interest, generation and lock ownership | Zero work causes no callback progress. Saturation, stale tickets, handle/root/ticket loss, close/drain, Host checkout reentrancy and unwind preserve exact generation/root ownership until settlement. Closing rejects new pins while a live accepted call can still settle; callbacks run outside structural locks. |
| Cancellation and terminal disposition | First cause and fresh independent drain deadline survive bounded progress without deadline extension. Host whole-call transfer acceptance/refusal and static fabricated-transfer rejection retain their legal complete owners. Late results still pass Core validation. Acknowledgement/destruction occurs once, and incomplete external shutdown is recorded as residual before local disposal rather than claimed complete. |
| Real capacity and reclamation | Actual local/shared-parent build/output/call/slot/scratch/cancel/transfer/cleanup capacity is held before side effects and until physical child destruction. Boundary, allocation-failure and two-root exhaustion cases recover original owners. Observe provisioning, simultaneous peak, largest request, transfer overlap, source-free publication and zero terminal controlled backing/parent charges separately from logical allowances. |
| Profile applicability and evidence scope | Native Host and manual static behavior, no-default and async-no-std static behavior, and actual ARM normal-library compile cells pass the registered commands. ARM compilation gives type/layout evidence only. Audit the concrete finite author declarations; arbitrary callbacks, allocator/stack/device fit and network behavior remain unqualified. |

If a reviewer falsifies an obligation, retain the non-accepted gate state and
repair only within an authorized source/evidence envelope. A changed public,
ownership, resource or protocol contract requires its normal architecture and
tranche review. After explicit exact-head independent gate acceptance, a separate
status-only transition by a non-author applies `ready -> passed` under
`PROJECT_GOVERNANCE.md`. This registration performs no such acceptance or transition.

## Exclusions and successor boundaries

The scope remains one startup complete Consumer-only registration, one eager
generation and one manual call/result opportunity, with repeated reads only after
terminal release. It does not establish multiple simultaneous generations/calls,
multiple bindings, a scheduler/worker/executor, pools, automatic retry, lazy/cache
planning, general ConsumedThing migration, broad package/milestone completion,
full performance workloads, ingestion, subscriptions/emission, Directory,
deployment or release readiness.

The deterministic binding is mock protocol evidence. Real Host Zenoh Consumer
qualification is the roadmap successor immediately after this architecture proof;
the earlier Producer network probe does not prove it. Real zenoh-pico runtime and
materially contrasting protocol-shape evidence retain their separate obligations.
Strict bounded JSON ingestion is a future capability under ADR-0021, not a missing
typed-input prerequisite. OPEN topics 0081 (reusable Plan versus Thing identity) and
0082 (logical versus physical subscriptions) remain non-blocking for this bounded
single-Consumer one-shot proof; it makes no sharing or long-lived ownership decision.
