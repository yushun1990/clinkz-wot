# Reusable Producer preparation across independent publications

This increment implements explicit reuse for Host/manual, loopback HTTP NoSec
Property Read. It does not claim independent acceptance, package/milestone
closure, production qualification or broader Producer-family reuse.
[Topic 0126](../../workspace/0126-reusable-producer-preparation.md) records the
first-principles reassessment and rejected alternatives. Exact contracts belong
to [Planning](../spec/planning.md#reusable-producer-preparation), the
[Binding SPI](../spec/binding-spi.md#reusable-http-producer-instructions) and
[Runtime Safety](../spec/runtime-safety.md#reusable-producer-definition-ownership).

## Actual reused work and independent lifetimes

`PreparedThing` remains a whole-description selection with exact coordinates and
actual provider identity. `ProducerCapability` still returns an independently
owned mapping for each selected operation/Form; that preparation can now check
and bind a supplied concrete HTTP definition. `ComposedProducerExposure` retains
its existing per-instance publication/retirement and complete native membership.
There is no shared-Thing wrapper, Consumer association copy, universal program,
mandatory cache, scheduler or per-Thing Runtime added to manufacture reuse.

The invariant compilation is the HTTP native response discriminator plus the
complete response contract and value/response validation trees. All native
applicability checks precede fresh lowering or borrowed dependency comparison;
reusing a supplied definition skips the block containing every invariant lowerer.
The compiler's `native_compilations` counter is incremented exactly in that
block, before constructing the common response/schema owners and native response
table. Pointer identity independently checks that every new mapping references
the original physical instructions. This is neither post-compilation interning
nor merely sharing transport or a separately prepared schema.

The checked input walk, normalized native response extraction, schema census and
comparison, endpoint checks, source TD parsing/interpretation, instance mapping
allocation/admission and final qualification still run. No total preparation-time
or throughput speedup is asserted. Ordinary fresh/unselected support probes may
still lower temporary definitions; supplied-definition probes and selected final
checks do not. The native connection may copy its small response table into
connection backing as accepted interaction work; it does not recompile it.

Names, TD IDs/titles, Form coordinates, actual Binding identity/generation and
native endpoints are fresh mapping/instance facts. Nested schema field names,
required sets and constraints, response order/status/success/media and operation
remain checked dependencies. Native correlation, timeout, route collisions,
listener setup and retirement belong to actual native participants. Complete
final advertisement, behavior, current authority, fresh request authorization,
results and cleanup remain independent logical/publication/work owners.

The original definition bank acquires provisional artifact/live/cleanup backing
before lowering and retains the actual physical bytes thereafter. Each program,
reusing provider and extracted definition retains that same owner; separate
exposure banks pay their actual description, mapping, behavior, participant,
publication, result/cleanup and final-check costs. Retiring the source never
transfers its physical charge to a sibling. Startup provider/raw registry
baseline backing and native SDK/OS allocations retain their existing declared
caller/Binding/deployment owners; this is not total process-RAM accounting.

## Executable evidence

The five new cases in
[the composed HTTP fixture](../../protocol-bindings/protocols/http/tests/composed_thing/reuse.rs)
exercise the production TD walk, actual HTTP compiler/validator/native transport,
Servient admission, complete final qualification, local publication and real TCP
requests. They use no test-only native provider or simulated publication kernel.

- **One lowering across three staged Things and four routes.** The source has
  Property `alpha`, one Form and its own listen address/Binding identity. A sibling
  has Property `beta`, two Forms, distinct paths/address/Binding identity and its
  own behavior/permission/account. A third has another name/endpoint and a
  conflicting logical slot. Exactly one actual lowering remains after all
  preparation, admission and final checks. All supplied-definition providers
  report zero lowerings, and all bound programs share the original compilation.
- **Independent actual behavior and publication.** A real request queued before
  publication cannot dispatch while installed closed. Two Things publish
  independently. The conflicting third publication fails after closed readiness,
  records its own failure, closes/releases its socket and leaves both siblings
  serving. Requests verify original recipient/Property coordinates and independent
  values. Denying only the sibling produces `NotInvoked` with original
  `AuthorizationDenied`, while the source's validated result remains readable.
  Restoring sibling permission after source retirement permits HTTP 200 with its
  own value. A subsequent HTTP 422 carries the originally prepared named response
  schema, explicit failure status and additional-response selection.
- **Independent retirement and original final release.** The source's unread
  delivered settlement blocks its retirement until acknowledgement. The sibling
  continues after that source closes and its original socket becomes bindable.
  Its original bank then contains only the shared physical definition charge.
  The failed publication bank and sibling exposure bank each return to zero
  independently. An explicit definition and finally a detached native program
  keep the original charge alive after all exposures/providers are gone. Dropping
  the final program releases live/artifact/cleanup charges; all sockets can be
  rebound. The measured definition in this fixture is **1,043 requested retained
  bytes** on the tested 64-bit Host, one artifact, independent of Thing count;
  this is not allocator overhead, SDK RAM, or a fleet cost estimate.
- **Changed dependencies refuse before effects.** Independent cases change value
  bounds/required fields, named response-schema constraints, native status,
  response success/media, explicit method, coding, security and extension meaning,
  and append an unsupported operation/Form. Each refuses the supplied definition
  with zero lowering and no listener. Changing the final description after
  preparation likewise refuses managed admission, invokes no behavior and returns
  the new instance bank to zero without changing original definition funding.
- **Native selection remains real.** Two compatible Forms with the same native
  method/path cannot become an installed route inventory. Two actual supporting
  registrations remain ambiguous. Neither case falls back to compilation or opens
  a socket. Shared definition identity does not bypass either refusal.
- **Actual supplied dependency remains qualified.** Substituting a differently
  compiled schema under the same Binding identity and native endpoint refuses
  final checking even when the old prepared mapping agrees with the TD. The
  actual supplied definition is checked at final qualification, not hidden by
  the expected old mapping. No fallback lowering or native setup occurs.
- **Original reservation rollback.** Saturating each of the five definition
  accounts in turn refuses before the lowering counter increments. Earlier
  provisional leases roll back, no native setup occurs, and removing the blocker
  returns all accounts to zero.

The existing `producer_installation` resource test now compares exact structured
schema growth against the scalar instruction owner, rather than assuming the old
inline private layout. It retains its original maximum-node, quota, disposal and
funded-at-free obligations. The native installation policy includes the shared
instruction allocation and destruction work. Existing complete composed HTTP/UDP,
Read/Write/collection/HTTPS/Action, schema/response and resource regressions remain
applicable. Their passing results do not extend this reusable definition's scope.

Parallel validation exposed a fixture address race: native `bind` tracing showed
one test reusing a released port-0 probe already advertised by another test.
The finite and composed Producer fixtures now keep their advertised TCP endpoints
distinct within each test binary. Deliberate collision cases still reuse the
same explicit address. No native runtime fallback/retry or collision weakening
was added to hide that test race.

Commands and exact checked commits are recorded in the PR. Focused evidence is
`cargo test --locked -p clinkz-wot-binding-http --test composed_thing managed::reuse -- --nocapture`;
full affected package/broker regression and authority/no-default checks are
separate from the automatic Git diff-hygiene status.

## Remaining limits

The definition is process-local and belongs to one concrete HTTP implementation
and validator/native policy. There is no persisted image, cross-version or
cross-Binding compatibility claim. Only the explicit NoSec Property Read mode
exports a reusable definition. Write/collections, HTTPS/live security services,
continuing Action and MQTT Producer reuse remain separate work; existing
specialized execution is retained. Whole TDs are still parsed/qualified per
instance, and native setup/collision work is still required. This fixture uses
independent listeners; it does not establish shared-listener native multiplexing,
Producer Host-loop composition, broad concurrency/scaling, constrained profiles,
remote discovery advertisement atomicity or v1 readiness.
