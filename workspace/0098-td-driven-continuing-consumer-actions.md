# TD-driven continuing Consumer Actions

Status: MIGRATED

## Evidence and alternatives

The existing finite Consumer seals only terminal application output and requires
explicit Action synchronicity. Extending that call with a status flag would lose
the native invocation token when the initiating exchange retires, confuse cancel
acknowledgement with completion and prevent independently selected control Forms.
The qualified HTTP Producer already supplies independent POST/GET/DELETE mappings
and an invocation store with epoch-qualified tokens.

Use a distinct Consumer Action association under existing v6 ownership, rather
than a finite compatibility wrapper or universal session. Planning selects each
described operation and actual services; concrete control mappings prove native
continuation compatibility with the invoke mapping. An opaque native token carries
no logical authority. The source-free runtime pins the original Consumer instance,
definition, services, continuation and prepaid cleanup through terminal settlement.
The HTTP Producer and Consumer share native pure lowering, retaining separate role
eligibility and deployment policy. Native envelopes and destination expansion
remain in HTTP; a wire Location never selects a control.

The first executable run exposed the existing 256-unit default compilation step
allowance versus the native 4096-unit pure callback bound. Use an explicit caller
allowance, as the MQTT typed facet already does; do not weaken the declared bound
or change a default profile to conceal the refusal. The bounds carrier now has a
common preparation name, with callers migrated directly.

## Ownership and falsification

Each invocation permits one native exchange at a time, while its identity survives
that exchange. Pending/error retirement retains the complete exchange and original
funding. Local cancellation never implies remote rollback. Late output still uses
the captured original validator and retains native result, validation error and
first local cause separately. Root loss falls back only to the Binding's finite
nonblocking local-abort contract; no detached cleanup or hidden remote cancel is
introduced. Terminal slot acknowledgement cannot make an old handle address reuse.

EXEC-ACTION-001, EXEC-DATA-001/EXEC-OUTCOME-001, PREP-SELECT-001, Binding SPI,
runtime safety, API ownership and WP-200/300/400/600 project this implemented
boundary. Real Engine Consumer-to-qualified-Producer HTTP evidence covers the
lifecycle and refusal/replacement/release cases. A downstream datagram fixture uses
different invoke/control implementations and delays/fails cleanup around an invalid
late result. Existing synchronous finite and notification evidence is retained.
Concrete HTTP limits belong in its README; capability availability belongs in
PLAN's matrix. No architecture gate, package or milestone is closed here.
