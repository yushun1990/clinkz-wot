# Real HTTP participation in the shared logical runtime

Status: MIGRATED

## Reassessment and smallest useful boundary

Basis: `742afac` (shared logical owner) plus `2773299` (prepared HTTP type
validation). The latter was still an open reviewed PR when this investigation
began; GitHub owns its merge state, not this record.

The working HTTP owner already implements bounded real socket/parser/reply I/O,
caller-clock request timeouts, local native disposal and a prepared actual JSON
validator. Its public root also funds aggregate Engine owners/results/cleanup
against original Host accounts. But its integrated root pairs one instance and
provider, the request ABI has only instance/correlation for a fixed Read, and the
public root imports preparation. Wrapping it
would not join HTTP to the one shared authority/behavior owner introduced by #230.

The shared finite owner already has independent typed native lifetimes, current
logical lookup, accepted-instance retention and complete original settlement.
Its raw facet lacked a clock/deadline path and any required validation service.
A ready HTTP listener would therefore neither carry over the old deadline
guarantee nor make a number-valued TD promise true. The real-wire test explicitly
contrasts raw HTTP 200/string with Required validation's 500/null on the same
prepared integer mapping. Raw behavior is intentional, not a qualification bug.

Select direct HTTP finite participation with those two necessary execution
contracts addressed in the same slice. Actual HTTP integration is possible now;
another mock qualification framework is not a prerequisite. This is progress
toward qualified exposure, not a claim of complete publication.

## Alternatives and ownership

- Adapt the old installation/permit/request/response ABI: rejected. It hides
  instance ownership in a route-shaped facade and does not remove the semantic
  root's upward dependency or provide shared dispatch.
- Move handler/authority into each native participant: rejected. It recreates
  the ownership defect already removed in #230.
- Delete the working funded public root now: rejected for this slice. The raw
  registry has no final-description publication or aggregate Host admission.
  Deletion before replacing those guarantees would discard useful correctness
  evidence and a functioning supported path. The old API has no compatibility
  claim; eventual replacement should remove it directly.
- Build complete general multi-provider publication first: deferred. Actual
  HTTP support, service enforcement and native retirement are required evidence
  for that join, and can be executed without inventing a certificate framework.

HTTP owns matching/correlation, native configuration, schema codec service,
socket/parser/reply and retirement. Core owns the output-service contract and
clock-qualified deadline representation. Servient owns the one behavior and
current acceptance, result bounds, required-service checks, paid traversal,
first failure and accepted retention. The new HTTP facet calls no old install
API and has no Servient normal dependency. Preparation/source loans end before
I/O. Native abort has independent NotDelivered/Unknown meaning; partial writes
never prove that the response was absent at the peer.
Native reply issuer/correlation also prevents substitution between sibling owners
with the same numeric identity. The actual service loan spans the synchronous
handler so dependency loss cannot discard its original validated late output;
future delivery still fails closed. Policy callbacks recheck the pair before
behavior entry.

## Migration and evidence

Reaffirm ADR-0025; no new architecture revision, state family, package/tranche,
schema/profile or global gate. Detailed owners are Interaction Core's service
contract, the module boundary, WP-400's finite execution scope and WP-600's native
HTTP scope. Existing raw callers migrate directly to explicit validation/time.
Prior review/CI and historical gates retain their exact revision scope; changed
Core/transport/finite evidence is rerun, not inherited as successor acceptance.
Affected requirements are EXEC-ID-001, EXEC-HANDLER-001, EXEC-DATA-001,
SPI-NATIVE-001, SPI-DELIVERY-001, SPI-RETIRE-001, SAFE-AUTH-001,
SAFE-CANCEL-001, SAFE-CLEANUP-001 and RES-WORK-001. PREP-COVER-001 and
SAFE-PUBLISH-001 continue to constrain the unimplemented complete exposure join.

Falsification uses the actual HTTP native facet, independent raw peers and public
Consumer. Cover shared mutable behavior through independent owners, closed-gate
traffic, malformed framing, schema/Unicode/integer checks, service absence/loss,
prepaid traversal and result bounds, expiry/clock errors, native start failure,
accepted/late output, partial writes, replacement, failed cleanup, last-root
disposal and sibling progress. Retain original-account regressions on the working
public path and normal-graph TD/Planning cuts on both execution facets.

Remaining qualified-exposure work is the actual final TD inventory joined to
every behavior/provider/service/response branch, aggregate owner admission,
native participation/readiness/collision and final endpoint/dependency checks,
followed by one Servient-local description/current-authority commit. Required
output validation and `activate_raw` establish none of that complete join.
