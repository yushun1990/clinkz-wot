# Review 11 — Engine architecture on master

**Scope.** Independent audit for Owner review of [master at d6a4c86b2629a930b5337913844d14a8fd3cfcf7](https://github.com/yushun1990/clinkz-wot/tree/d6a4c86b2629a930b5337913844d14a8fd3cfcf7). The criteria are the project's enduring goals and the W3C interaction and TD models. Findings below record observed behavior, the strength of the evidence and the kind of decision each warrants. [Project goals](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/docs/architecture/00-system-goals-and-context.md) · [WoT Architecture 1.1](https://www.w3.org/TR/2023/REC-wot-architecture11-20231205/) · [Thing Description 1.1](https://www.w3.org/TR/2023/REC-wot-thing-description11-20231205/)

**Assessment.** Master can consume and expose Things through real HTTP and MQTT I/O. More than one logical instance can use common prepared meaning or native infrastructure while retaining its own authority, calls and results. HTTP finite Read demonstrates checked reuse across different endpoints. Caller-owned finite Read and continuing Action execution also work. Each result has a narrower boundary than “the Engine is portable and compiles a Thing once.”

Three input comparisons exposed failures on ordinary public paths. A Consumer refuses the standard paired TD context, a Producer publishes a Property with no Forms, and continuing Action preparation can discard the only usable Query alternative. There is also a concrete ordering error in aggregate Action work accounting. The most consequential open authority question is what a managed finite Producer can establish about the recipient reported by a Binding at dispatch. The HTTP implementation supplies the right recipient in the traced path.

### F1. The semantic resolver refuses the standard TD compatibility context

**Implementation defect · High · reproduced · correction.** TD 1.1 specifies the 2019 context followed by the 2022 context when TD 1.0 Consumers may be present. The library exposes that exact combination. The resolver recognizes either URI only while its seed flag is clear. It rejects the second URI, and finite selection eventually reports an unsupported operation. The project can generate a TD that its own HTTP Consumer cannot prepare. Arbitrary remote context retrieval is a separate policy decision. [TD 1.1 §5.3.1.1](https://www.w3.org/TR/2023/REC-wot-thing-description11-20231205/#thing) · [context builder](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/td/src/components/context.rs#L94) · [resolver](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/td/src/semantic.rs#L399) · [selection error handling](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/planning/src/open_consumer.rs#L785)

**Control.** Prepare one NoSec, read-only integer Property named `level` with an absolute loopback HTTP Form. The 2022 context alone succeeds. Set only `@context` to the serialized result of `Context::new().with_1_0_compatibility()` and the same public registry, compiler and bank return `UnsupportedOperation`. Other roles use the same resolver. The executed comparison covers the finite Consumer. ### F2. Managed publication can advertise a Property with no Forms

**Implementation defect · High · reproduced · correction.** An InteractionAffordance requires a nonempty Form array. Property deserialization requires the member but accepts an empty vector. ### F3. Continuing Action selection can throw away the usable control family

**Architectural/design defect · Medium · reproduced · correction of selection semantics.** Planning keeps the first individually supported Form for each operation and skips subsequent alternatives. ### F4. Finite ingress relies on native recipient attribution at the last authority boundary

**Unresolved architectural question · High potential impact · confirmed reliance, conditional risk · investigate the dispatch contract.** Managed staging checks the participant, issuer, instance and definition coverage. At dispatch the runtime verifies its Servient issuer and ingress gate. The final lookup then accepts a current instance in that Servient with the candidate's key and a matching target/operation. The candidate carries no originating publication or finite route. This lookup does not independently join the incoming participant to the behavior it selects. A Binding correlation error could therefore direct work to a sibling with a matching behavior, subject to that behavior's own validation and authorization. The current HTTP implementation sets the key from its captured configuration. No HTTP misdelivery was observed. ### F5. QueryAllActions performs Engine work before checking its work allowance

**Implementation defect · Medium · confirmed by source · correction.** The managed dispatch calls the Binding's aggregate setup, obtains its inventory, then builds a vector of handles. For each native reference it searches the Servient invocation store. Only afterwards does `query_raw_actions` consume the Engine's `HandlerSteps` allowance. HTTP charges `BindingPolls` for its own aggregate setup. A short Engine budget can therefore incur allocation and up to inventory-length × store-length comparisons before refusal. The inventory and store limits bound the cost. The later prepayment and authorization still protect member views and handler callbacks. A test entering at `query_raw_actions` cannot detect work in its caller. [Dispatch ordering](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/servient/finite/src/action.rs#L580) · [Engine prepayment](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/servient/finite/src/action.rs#L1097) · [HTTP charge](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/protocol-bindings/protocols/http/src/action_producer.rs#L405) · [existing aggregate test](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/protocol-bindings/protocols/http/tests/query_all_actions.rs#L871)

### F6. Preparation reuse stops at different boundaries in each family

**Missing or incomplete capability · High · confirmed by source and I/O · implementation, with the reusable unit still open.** Preparing finite interactions, a continuing Action and a notification from the same immutable TD starts Basic admission three times. Finite and Action selection can share a semantic loan across operations on one Form. Producer `visit_thing` enters the resolver inside its operation loop. The initial preparation, staged admission and final publish each parse and walk the Producer description. The audit found no evidence that every final qualification can be dropped, that a shared native listener proves reusable compilation, or that every historical Read carrier is obsolete. F1–F5 also show that accepting a lifecycle proposal would leave specific interoperability, selection, authority and accounting questions to settle. The roadmap records scope and historical evidence. The source and executions above establish what works here.
