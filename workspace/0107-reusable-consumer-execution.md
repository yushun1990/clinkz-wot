# Reusable Consumer execution content

Status: MIGRATED

The first increment in Review 09 exposes an ownership defect in the finite
handoff: `ConsumerDefinition` combines immutable operation/data meaning, an
exact native mapping, data/access services and the bank required at runtime.
The real HTTP artifact contains the full URL, method and headers. Retargeting
that artifact is invalid; sharing the complete old definition also shares its
policy and funding. Interning separately compiled schemas proves neither reuse
of preparation nor independent instance binding.

Selected correction: retain source-independent affordance/operation/data-role
content once, under its original physical funding. Pure endpoint qualification
borrows and compares that content against the actual TD and compiles each native
mapping normally. A qualified definition retains the content, native artifact,
actual executor/configuration and data service. Independent bindings attach
access policy and instance accounts before the existing runtime attaches logical
authority. Calls/results keep those owners rather than copying their content.
No foreign-bank check on instance records is removed.

Compare alternatives: only sharing the collection schema leaves the handoff
coupled; sharing the old complete definition shares mutable dependencies;
universal native operands invent HTTP compatibility; a cache adds an unrelated
identity/eviction problem. The chosen boundary preserves the actual native
compiler and call/settlement mechanisms. Semantic content itself has no executor
or Arc field; the current Host representation chooses funded shared ownership.

Affected owners: PREP-REUSE-001 and the finite implementation in Planning;
EXEC-ID-001/EXEC-DATA-001 in Core; captured dependencies in Binding SPI;
independent admission/result ownership in runtime safety; RES-OWNER-001 and
physical accounting in Foundation; corresponding API/work-package projections.
Producer complete qualification and the current HTTP concurrency policy remain
evidence obligations. No general DataSchema/security/profile acceptance follows.

Falsifiers: a second member/name table on reuse, effect through an incompatible
mapping/service, identity collapse across equal numeric slots, cross-instance
policy or revocation, a reservation migrating to another bank, or physical
release before the last late/unread result. Real Engine HTTP peers and allocator
measurements over increasing bounded instance counts exercise these claims.

The detailed boundary is migrated to Planning, Core, Binding SPI, runtime safety
and Foundation, with API/work-package projections. Review 09/ADR-0025 already
select prepare-once/checked-bind-many; this implements that direction without a
new architecture model or package gate. The real HTTP fixture and measurement
evidence define the implementation scope. Independent architecture/implementation
acceptance remains necessary; migration here is not an acceptance claim.
