# Review 11 — Engine architecture on master

**Scope.** Independent audit for Owner review of [master at d6a4c86b2629a930b5337913844d14a8fd3cfcf7](https://github.com/yushun1990/clinkz-wot/tree/d6a4c86b2629a930b5337913844d14a8fd3cfcf7). The criteria are the project's enduring goals and the W3C interaction and TD models. Findings below record observed behavior, the strength of the evidence and the kind of decision each warrants. [Project goals](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/docs/architecture/00-system-goals-and-context.md) · [WoT Architecture 1.1](https://www.w3.org/TR/2023/REC-wot-architecture11-20231205/) · [Thing Description 1.1](https://www.w3.org/TR/2023/REC-wot-thing-description11-20231205/)

**Assessment.** Master can consume and expose Things through real HTTP and MQTT I/O. More than one logical instance can use common prepared meaning or native infrastructure while retaining its own authority, calls and results. HTTP finite Read demonstrates checked reuse across different endpoints. Caller-owned finite Read and continuing Action execution also work. Each result has a narrower boundary than “the Engine is portable and compiles a Thing once.”

The first pass reproduced three independent failures. A Consumer refuses the standard paired TD context, a Producer publishes a Property with no Forms, and continuing Action preparation can discard the only usable Query alternative. Aggregate Action work also begins before its Engine allowance is checked (F1–F3, F5).

**Second-pass judgment.** Generic Consumer Planning can exclude a third-party implementation before its compiler is called (F12). HTTP already correlates shared-listener input to its original route lease, which narrows the finite recipient question (F4). Two newly isolated consequences affect independent progress. A retained finite Producer exchange can close its participant and, on reconciliation, revoke the published Thing (F15). A completed, unread MQTT publication can hold the shared writer against a second Thing (F16). F7 and F9 extend existing findings with checks at the first native effect and at an empty receive. F13–F14 distinguish working adapters from public names without execution callers.

### F1. The semantic resolver refuses the standard TD compatibility context

**Implementation defect · High · reproduced · correction.** TD 1.1 specifies the 2019 context followed by the 2022 context when TD 1.0 Consumers may be present. The library exposes that exact combination. The resolver recognizes either URI only while its seed flag is clear. It rejects the second URI, and finite selection eventually reports an unsupported operation. The project can generate a TD that its own HTTP Consumer cannot prepare. Arbitrary remote context retrieval is a separate policy decision. [TD 1.1 §5.3.1.1](https://www.w3.org/TR/2023/REC-wot-thing-description11-20231205/#thing) · [context builder](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/td/src/components/context.rs#L94) · [resolver](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/td/src/semantic.rs#L399) · [selection error handling](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/planning/src/open_consumer.rs#L785)

**Control.** Prepare one NoSec, read-only integer Property named `level` with an absolute loopback HTTP Form. The 2022 context alone succeeds. Set only `@context` to the serialized result of `Context::new().with_1_0_compatibility()` and the same public registry, compiler and bank return `UnsupportedOperation`. Other roles use the same resolver. The executed comparison covers the finite Consumer. ### F4. Finite dispatch trusts the Binding for original native recipient attribution

**Unresolved architectural question · Medium assurance priority · confirmed trust boundary, no demonstrated misdelivery · further investigation only for a supported case that crosses it.** The finite SPI gives the Binding the original captures, native matching and exclusive reply. Managed staging verifies the participant's readiness and coverage. Servient checks the driving issuer and ingress gate, requires a single candidate, finds the current logical incarnation and behavior, checks data and permission, then fences the callback and delivery. The lookup takes the candidate's instance key as supplied. An incorrect native attribution would violate the Binding contract. The source establishes that dependency. It supplies no example of a conforming attribution that sends a request to the wrong Thing. ### F5. QueryAllActions performs Engine work before checking its work allowance

**Implementation defect · Medium · confirmed by source · correction.** The managed dispatch calls the Binding's aggregate setup, obtains its inventory, then builds a vector of handles. For each native reference it searches the Servient invocation store. Only afterwards does `query_raw_actions` consume the Engine's `HandlerSteps` allowance. HTTP charges `BindingPolls` for its own aggregate setup. A short Engine budget can therefore incur allocation and up to inventory-length × store-length comparisons before refusal. ### F15. A finite Producer exchange failure can retire its serving participant

**Architectural/design defect · High for sustained managed finite service · reproduced through managed publication and its normal execution turn · reconsider the scope of retirement.** `FiniteIngress<R>` moves the original request, candidate list and exclusive reply opportunity together. The pending reply keeps that ingress, the semantic result and effect. This protects original exchange ownership through refusal, replacement and cleanup. The finite SPI offers no operation for the Engine to retire just its already retained exchange and resume serving on the same participant. In the Host runtime, expiry of that exchange's original request deadline or a native send error calls `fail`, closes the ingress gate and drives the entire participant to `Closed`. Reconciliation of a **committed member's** failure subsequently revokes that logical Thing, including its other affordances. A separately published Thing can keep its own lease. ### F16. A terminal MQTT Producer result holds a shared native writer

**Missing or incomplete capability · Medium for independent progress on the shared MQTT service · reproduced with two published Things · determine whether the supported profile requires independent result retention.** The MQTT service serializes packet writes with one session-wide busy flag. A successful publication reaches its local delivery edge and `poll_retire` returns ready. Only destruction of the native publication clears the flag. The Servient keeps that native owner, its original input and funding until the caller acknowledges or drops its outcome. The two policies together extend writer occupancy across the unread-result interval. Serializing an incomplete packet and marking a partially written stream uncertain are justified native responsibilities. The observed extra dependency concerns an already completed packet. [MQTT admission](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/protocol-bindings/protocols/mqtt/src/native.rs#L647) · [native retirement and destruction](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/protocol-bindings/protocols/mqtt/src/native.rs#L816) · [Servient acknowledgement](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/servient/finite/src/notification_publication.rs#L213) · [partial-write evidence](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/protocol-bindings/protocols/mqtt/tests/producer_events.rs#L811)

**Broker control.** Two independent Things used distinct topics through one healthy MQTT service. A's first result reached `LocallyPublished` and its owner retained it without acknowledging it. B's publication returned `Backpressure` with its original input, B's description remained current and the local publication count stayed at one. After A acknowledged, B retried with the same payload bytes and the count reached two. This identifies a real cross-Thing capacity limit, with no observed retargeting, data loss or subscriber-delivery claim. [Producer publication fixture](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/protocol-bindings/protocols/mqtt/tests/producer_events.rs#L554) · [shared-session setup](https://github.com/yushun1990/clinkz-wot/blob/d6a4c86b2629a930b5337913844d14a8fd3cfcf7/protocol-bindings/protocols/mqtt/tests/producer_events.rs#L735)

**Consumer comparison.** Finite HTTP Consumer exchange success or failure releases native occupancy once. An unread result stays attached to its original funding, and disposing it cannot release a successor's socket. Managed `ConsumerCalls` releases its registry slot on transfer to the result owner. Configured outstanding/per-Thing credit can still refuse further admissions while the result is held. A continuing Consumer Action separately owns its Invoke/control exchange and any original continuation. A notification subscription and a reciprocal response each have a close/retirement contract. MQTT Consumer tests also preserve a sibling handshake when another subscription closes during shared setup. These are distinct lifetimes across the two roles. An unread result does not by itself establish an Engine-wide native lock. | The unit being validated is sometimes smaller than the claim made afterwards. | A context URI is recognized in isolation (F1).
