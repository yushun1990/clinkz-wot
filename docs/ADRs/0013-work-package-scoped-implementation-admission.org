#+title: ADR-0013: Scoped implementation admission
#+date: 2026-07-22
#+status: Accepted

* v6 amendment and rationale

Keep proportional dependency-complete scope/review under ADR-0025. The former
six-global-gate, GATE-5 and mandatory proof ordering are superseded. Their original
rationale is retained in Git at the v5.1 predecessor; they are not inherited v6
gates. A documentation authority migration is not runtime implementation admission.

Architecture-sensitive implementation identifies its exact successor requirements,
affected files/features, actual predecessors, public ownership/lifecycle/resource
changes, removed APIs and falsifiable completion evidence. The existing work-package
index records admitted tranches when required; a PR may carry ordinary bounded
work under project governance. No new tracker or checklist is required.

No source scope may choose between conflicting active owners or treat an
unimplemented dependency as available. Independent review reconstructs material
API/architecture/lifecycle/gate claims from the exact tree and evidence. Ordinary
local work follows AGENTS.md and project governance's proportional rule; every
change does not acquire an extra independent architecture gate.

Target measurements follow implementation. Define applicable workload, boundary,
oracle and required evidence before claiming completion; neither historical green
checks nor structural checks qualify new behavior. Actual publication, cancellation,
late outcomes and final release need focused real execution for claims about them.
No number of protocol fixtures is an architecture generality gate.

An intersecting counterexample triggers scoped impact review and correction of
all affected owners; preserve demonstrably disjoint work. An open investigation
is evidence to assess, not an automatic repository-wide freeze. Completed
historical tranches remain revision-scoped and cannot grant successor admission.
The v6 package graph distinguishes runtime, optional preparation and product
qualification; package completion is not an unconditional start barrier.

* Alternatives

Blanket global implementation freeze delays independent useful work and is
rejected. Self-declared architectural readiness and inherited gate acceptance
hide material conflicts and are also rejected. Scope and evidence must match
the actual risk, with one recoverable reviewed change boundary.
