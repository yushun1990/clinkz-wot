# Servient logical runtime — v6.0

Servient owns live logical instances and current execution authority, not native
network topology. It composes optional preparation, security/validation services
and Binding capabilities without interpreting protocols.

## Instance and acceptance

A local reference is qualified by its issuer/registry, slot, generation and
particular admitted obligation, or an equivalent lifetime proof. Neither a TD id,
endpoint, Rust type, content digest nor copied generation authorizes a call.
Several instances may share one description or physical runtime independently.
One logical instance can also participate in several independent Binding
runtimes under that same authority and captured behavior owner. Native runtime
retirement is not logical revocation; it cannot revoke a sibling's acceptance.

Consumer use selects a prepared candidate, checks policy/data/capacity and owns
the entire conversation/result/cleanup obligation before effects. Deferred pure
preparation belongs to a separate admitted coordinator. Completed construction
never creates current authority by itself. Persistent finite associations retain
checked mappings without idle call storage; explicit finite work owners supply
admission/progress capacity independently. The exact scopes and retention rules
are owned by [Runtime Safety](../spec/runtime-safety.md).

Producer setup validates known requirements and actual behavior/providers.
The bounded candidate secures rollback before the Binding takes a closed
endpoint. Planning qualifies the exact final TD against current providers.
Acquire the selected members with their rollback storage, using any concrete
slots already set aside for this candidate. Publication commits final coverage,
readiness, behavior, authority and gates together after the last callback.
A failed candidate returns its inputs and releases its own participants.
If a published operation later reveals a deterministic support gap present at
commit, fence the affected acceptance and requalify it.

Servient accepts exclusive work only with the original permission and usable
backing for the owed outcome and retirement. Publication can share call capacity
across idle instances. Native settlement can free an active exchange while its
unread or caller-held result still owns its backing. The Binding determines
native concurrency and final physical release. [Runtime Safety](../spec/runtime-safety.md#finite-producer-participation-and-work-capacity)

Optional [Host Producer turns](../spec/runtime-safety.md#host-producer-execution-turns)
retain typed Servient progress with the existing erased native members. They
compose with independent Consumer capacities, without owning a scheduler or
changing publication/result ownership. Original revoked Action cleanup no longer
requires an application handle inventory; acknowledgements remain explicit.

Native candidates retain original logical tokens/captures and backing. Servient
checks current identity, publication, policy, data and capacity independently per
recipient, captures behavior and reply capability, and dispatches outside locks.
Native ACK/control traffic is not application acceptance. Pending/late work never
looks up a replacement handler or maps an old packet into a successor slot.

In the Host finite and continuing Action Consumer owners, mutable registry
access ends before linked authorization, data, native progress or destruction. Reserved original slots and
separately retained passive controls keep cancellation visible during checkout.
A public drive bounds synchronous reentry through siblings or defers nested progress. [Runtime Safety](../spec/runtime-safety.md)
owns the callback, handoff, wake and funding guarantees; this is a correction to
those distinct owners, not a shared scheduler or automatic execution model.

The finite `ConsumerOwner` creates instance authority and consumes named association authority;
application handles/views are non-revoking. Explicit removal, replacement and
shutdown fence original permission before releasing mappings outside borrows.
Its own public ID/configuration lookup recovers management and operation access
after every view is lost; ID-based commands target the current registration,
while original snapshots support conditional management. Named access profiles
share one Thing identity and retain independent policy/mapping selections.
Execution capacity remains independently supplied. Native I/O wakes alone do not
schedule lifecycle cleanup: the application supplies lifecycle-command, cyclic
or actual timer turns and observations of the supplied monotonic clock. A logical
deadline is no scheduled timer. Actual aggregate control loss locally disposes
abandoned finite work rather than stranding it behind surviving handles;
explicit close keeps incremental cleanup access. Runtime Safety owns these
registered/standalone, progress and qualified final-disposal contracts.

## Distinct lifetimes

Action invocation state can outlive its initiating exchange. A root status query
is a separate finite observation of original invocation owners; native aggregation
and correlation remain at the Binding. Acknowledgement transfers result retention
through settlement disposal. Logical notification
conversations own establishment/control/delivery/stop and reciprocal responses
where promised. Producer sources can exist with zero subscribers. Native broker
subscribers are not necessarily Engine-owned logical subscriptions. Details are
owned by [Interaction Core](../spec/interaction-core.md).

Destroy/replacement revokes new acceptance first, then cancels/drains accepted
owners. Logical settlement, local release, remote residue and infrastructure
failure/retirement are separately observable. No transition label proves another
owner's release. Shared native participants retain their siblings' leases.
Explicit infrastructure shutdown belongs to its authorized physical owner and
revokes/drains all dependents it affects.

[Runtime Safety](../spec/runtime-safety.md) owns cancellation/cleanup/publication;
[state-machines.toml](../state-machines.toml) projects semantic boundaries, not
mandatory public guard families. It intentionally does not prescribe the old
prepared/active/committed route ABI, fixed scheduler lanes or per-family copies
of the same resource framework.
